# Правила розробки (Development Rules)

Цей файл містить набір строгих правил, яких я маю дотримуватись під час розробки цього проєкту.

## 1. Архітектура та Технології
- **Frontend:** React + TypeScript (через Vite). Без TailwindCSS, тільки Vanilla CSS (Design System у `index.css`).
- **Backend:** Python + FastAPI + SQLAlchemy 2.0 (з Alembic для міграцій).
- **База даних:** PostgreSQL.
- **Дизайн:** Темний мінімалізм (Glassmorphism, фон `#08080f`) з неоновим рожевим акцентом `#e359ac`.

## 2. Код-стайл та Патерни
- **React:** Завжди використовувати функціональні компоненти з Hooks (`useState`, `useEffect`, `useContext`).
- **CSS:** Всі кольори, шрифти та відступи мають братися з CSS-змінних (`var(--...)`) заданих у `:root` файлу `index.css`.
- **inline-styles:** При використанні inline styles у React, обов'язково перевіряти написання у `camelCase` (напр., `justifyContent`, а не `justify-content`).
- **Backend:** Всі моделі бази даних повинні мати чітку типізацію та зв'язки. Enum мають бути синхронізовані між бекендом та фронтендом.

## 3. Git та Коміти
- Кожен значний етап (мінорний чи мажорний) має завершуватися комітом.
- Формат повідомлень комітів повинен відповідати правилам, описаним у `COMMIT_CONVENTION.md` (двомовний запис).

## 4. Документація
- Всі значні зміни повинні відображатись у `walkthrough.md` та/або `implementation_plan.md`.
- Помилки та отриманий досвід фіксувати у `LESSONS.md`.
